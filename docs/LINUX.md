# Linux Guide

VX6's currently implemented IPsec dataplane is Linux-only and depends on
strongSwan, kernel XFRM, and the privileged `vx6-ipsecd` service. This is a
prototype install path, not yet a one-file or zero-configuration installer.

## Build

Install Go 1.24 or newer, strongSwan, and nftables, then build both binaries:

```sh
make build
```

This creates `vx6` and `vx6-ipsecd`. `make package-linux` creates an amd64
bundle containing both binaries, the systemd units, and an installer.

## Configure the IPsec Helper

For an Arch package or standalone bundle, configure the helper once for the
normal login account:

```sh
sudo vx6-setup "$USER"
vx6 doctor
```

`vx6-setup` writes the selected account's actual UID and primary GID into the
root-owned `/etc/vx6/ipsecd.json`, starts the installed strongSwan service, and
enables `vx6-ipsecd.service`. It does not add the account to a supplementary
group, so no logout is needed. Run the VX6 CLI as that normal login user, not
with `sudo`; using `sudo` changes the home/config directory and identity.

The standalone installer supports Arch and Debian/Ubuntu and installs
strongSwan/nftables before configuring the helper:

```sh
sudo ./install.sh "$USER"
```

The bundle is generated by `make package-linux`. The Arch recipe packages the
same binaries and setup helper; after installing the package, run
`sudo vx6-setup "$USER"`.

## Two-Peer Setup

Follow the step-by-step [command workflow](commands.md): initialize each node
with its reachable global IPv6 address, exchange signed endpoint records, add
the other peer record, start both nodes, and verify local prerequisites with
`vx6 doctor`. Start with a TCP service, then test UDP separately.

IPv6 routing and host firewalls must permit the VX6 TCP listener (default
4242), the UDP service port (default 4244), the liveness hint port (default
4243), IKE over UDP/500, and ESP (IP protocol 50). The precise ports follow the
configured listener port. VX6 does not provide NAT traversal.

`vx6 doctor` checks local configuration, a usable IPv6 address, the helper
socket, and whether the node is running. It does not establish a remote SA or
prove service data crossed ESP. See [IPsec operations](ipsec.md) and
[service boundaries](services.md).

## Current Boundaries

- TCP services and explicitly configured UDP datagram services are available.
- Public services still require an authenticated IKE/IPsec peer.
- UDP forwarding is not a general raw-IP tunnel and is not automatic WebRTC
  ICE/STUN/TURN integration.
- QUIC and arbitrary Layer-3 tunneling are not active.
- Debian/RPM native packages, upgrade/rollback automation, and signed release
  artifacts are not implemented. The bundle and Arch package still need clean
  installation and upgrade testing before being treated as production-ready.
